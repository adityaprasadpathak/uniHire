# UniHire - Next-Generation AI-Powered Hiring Platform

UniHire is a modern recruitment and talent acquisition platform featuring AI resume parsing, ATS scoring, AI cover letter generation, automated resume tailoring, pgvector-based semantic search, OpenSearch full-text querying, real-time WebSocket chat, background job orchestration, and caching with rate-limiting.

---

## Architecture Overview

UniHire leverages a distributed microservice-ready modular architecture designed for high scalability, fast search response times, and asynchronous AI workloads:

- **Spring Boot 4.1.1 (Java 27)**:
  - *Why it's needed*: Serves as the core enterprise backend application engine, providing REST APIs, Spring Security with stateless JWT filter chains, transactional JPA management, and integration with Spring AI.
- **PostgreSQL with `pgvector` Extension**:
  - *Why it's needed*: Serves two vital roles in a single database:
    1. **Primary Relational Store**: Stores system entities such as users, candidate profiles, work experiences, job postings, applications, and saved resume versions.
    2. **Vector Database (`pgvector`)**: Stores high-dimensional 3072-dimension vector embeddings generated by Google Gemini to perform semantic cosine similarity search for candidate-job matching and intelligent recommendations.
- **OpenSearch 2.19.0**:
  - *Why it's needed*: Provides high-performance, fuzzy full-text keyword querying and faceted filtering (by location, department, experience level). Works alongside `pgvector` to provide a robust hybrid search pipeline (OpenSearch for lexical matching + pgvector for semantic conceptual matching).
- **Redis 7+ (Lettuce Client)**:
  - *Why it's needed*:
    1. **Caching Layer**: Caches expensive candidate profile views, dashboard metrics, and recommendation queries to eliminate repeated heavy database queries.
    2. **API Rate Limiting**: Enforces token-bucket rate limits per client IP or user token to protect endpoints from abuse, configured with a resilient fail-open policy if Redis is unreachable.
- **JobRunr 7.3.2**:
  - *Why it's needed*: Asynchronous distributed background job orchestrator backed by PostgreSQL. Offloads long-running, CPU-intensive, or API-heavy background tasks (such as AI resume parsing, vector indexing, and ATS score computation) away from HTTP request threads, preventing request timeouts. Includes an embedded dashboard at `http://localhost:8000/dashboard`.
- **MinIO / Cloudflare R2 (S3-Compatible Object Storage)**:
  - *Why it's needed*: Securely stores binary document uploads (original candidate resumes in PDF/DOCX, portfolios, and certification attachments) rather than bloating the relational database with large byte blobs.
- **Apache Tika**:
  - *Why it's needed*: Embedded content analysis toolkit that parses and extracts raw text metadata from diverse document formats (PDF, DOCX, DOC, TXT) before passing the content to AI models for structured JSON extraction.
- **Spring AI & Google Gemini (Chat & Embeddings)**:
  - *Why it's needed*: Powers the core intelligence of the platform:
    1. **Structured Parsing**: Converts unstructured text extracted from resumes into normalized JSON schemas.
    2. **ATS Scoring & Feedback**: Analyzes resumes against job descriptions to provide detailed compatibility scoring and actionable feedback.
    3. **Resume Tailoring**: Rewrites experience bullet points and professional summaries tailored to target industries, countries, and roles.
    4. **Embedding Generation**: Produces dense vector representations of jobs and candidate skills using Gemini's text embedding models.
- **Spring WebSocket with STOMP over SockJS**:
  - *Why it's needed*: Enables instantaneous, bidirectional, real-time messaging between employers and candidates without client polling.
- **React 19 / Vite Frontend**:
  - *Why it's needed*: Provides an interactive, responsive user interface with real-time resume live previewing across 8 ATS-ready templates, candidate drag-and-drop boards, analytics charts, and instant messaging.

## Infrastructure Setup Options

You can set up the required dependency services (PostgreSQL with pgvector, Redis, OpenSearch, MinIO) in two ways:

1. **Option A: Quick Docker Compose (Recommended for single-machine development)**
2. **Option B: Manual / Network-based Setup (On your LAN or distributed across servers/VMs)**

---

### Option A: Quick Infrastructure Setup via Docker Compose

A pre-configured [`docker-compose.yml`](docker-compose.yml) is included in the project root containing PostgreSQL (`ankane/pgvector:v0.5.1`), Redis 7 Alpine, OpenSearch 2.19.0, and MinIO.

Run:
```bash
docker compose up -d
```

Verify that all services are running:
- **PostgreSQL (pgvector)**: `localhost:5432` (db: `unihire`, user: `postgres`, pass: `password`)
- **Redis**: `localhost:6379`
- **OpenSearch**: `localhost:9200`
- **MinIO S3**: `localhost:9000` (Console UI at `http://localhost:9001`, user/pass: `minioadmin` / `minioadmin`)

---

### Option B: Manual / Network-Based Setup (Bare-metal or Remote LAN Machines)

If running dependencies directly on native machines, WSL2, or dedicated nodes on your local network (e.g., `192.168.0.x`):

#### 1. PostgreSQL with `pgvector`
- Install PostgreSQL 16+ on your machine or target server.
- Install the `pgvector` extension ([pgvector installation guide](https://github.com/pgvector/pgvector#installation)):
  - **Linux (Ubuntu/Debian)**:
    ```bash
    sudo apt install postgresql-16-pgvector
    ```
- Create the database and enable the extension:
  ```sql
  CREATE DATABASE unihire;
  \c unihire;
  CREATE EXTENSION IF NOT EXISTS vector;
  ```
- *Network Access*: Edit `postgresql.conf` (`listen_addresses = '*'`) and `pg_hba.conf` to allow connections from your dev machine's subnet.

#### 2. Redis
- Install Redis 7+ (`sudo apt install redis-server` or Windows binary).
- By default, Redis binds only to `127.0.0.1`. If running on a separate network machine (e.g. `192.168.0.188`), update `/etc/redis/redis.conf`:
  ```text
  bind 0.0.0.0
  protected-mode no
  ```
- Restart Redis: `sudo systemctl restart redis-server`
- Verify connectivity from your dev machine: `redis-cli -h <TARGET_IP> ping` (should reply `PONG`).

#### 3. OpenSearch
- Download and run OpenSearch 2.19.0+ ([OpenSearch downloads](https://opensearch.org/downloads.html)).
- In `config/opensearch.yml`:
  ```yaml
  cluster.name: unihire-cluster
  network.host: 0.0.0.0
  discovery.type: single-node
  # Optional: disable security plugin for simplified local dev if not using SSL certificates
  plugins.security.disabled: false
  ```
- Start OpenSearch: `./bin/opensearch`
- *Note*: UniHire's local configuration includes trust manager bypasses for internal self-signed network certificates (e.g. `https://192.168.0.188:9200`).

#### 4. MinIO / S3 Storage (Optional)
- Download MinIO binary and start server:
  ```bash
  minio server /data --console-address ":9001"
  ```
- Or point to any S3-compatible service or Cloudflare R2 (configured in `application-local.yml`).

#### Point UniHire to Your Network Services:
Update [`src/main/resources/application-local.yml`](src/main/resources/application-local.yml) or supply environment variables with your target network IPs:
```yaml
spring:
  datasource:
    url: jdbc:postgresql://192.168.0.188:5432/unihire
    username: postgres
    password: your_postgres_password
  data:
    redis:
      host: 192.168.0.188
      port: 6379
  opensearch:
    uris: https://192.168.0.188:9200
    username: admin
    password: your_opensearch_password

minio:
  url: http://192.168.0.138:9000
  access-key: minioadmin
  secret-key: minioadmin
  bucket: unihire-local
```

## Local Setup & Running Instructions

### Step 1: Configure Backend Environment Variables

Review [`src/main/resources/application-local.yml`](src/main/resources/application-local.yml) or set your environment variables.

If running on Windows PowerShell:
```powershell
$env:GEMINI_API_KEY = "your_actual_gemini_api_key"
$env:JWT_SECRET_KEY = "your_secure_256_bit_jwt_secret_key"
```

If running on Linux / macOS Bash:
```bash
export GEMINI_API_KEY="your_actual_gemini_api_key"
export JWT_SECRET_KEY="your_secure_256_bit_jwt_secret_key"
```

---

### Step 2: Run the Backend (Spring Boot)

#### On Windows (PowerShell):
```powershell
# Set Java Home to JDK 27 (adjust path as needed)
$env:JAVA_HOME = "C:\Users\<YOUR_USER>\.jdks\openjdk-27.0.1.0.2"

# Compile and run with the 'local' profile active
.\gradlew.bat bootRun --args='--spring.profiles.active=local'
```

#### On Linux / macOS:
```bash
./gradlew bootRun --args='--spring.profiles.active=local'
```

Once started:
- **API Server**: `http://localhost:8080`
- **Swagger UI (Interactive API Docs)**: `http://localhost:8080/swagger-ui/index.html` (or `http://localhost:8080/swagger-ui.html`)
- **OpenAPI 3 JSON Spec**: `http://localhost:8080/v3/api-docs`
- **JobRunr Background Dashboard**: `http://localhost:8000/dashboard`

---

### Step 3: Run the Frontend (React / Vite UI)

Navigate to the frontend application directory:

```bash
cd c:\reactProject\uniHire-frontEnd\apps\uniHire-ui
```

Install dependencies:
```bash
npm install
```

Start the Vite development server:
```bash
npm run dev
```

Access the frontend application at: **`http://localhost:5173`** (or the host port printed in the terminal).

## Key Features & Endpoints

- **Authentication & Security**:
  - `/api/auth/login`, `/api/auth/register`, `/api/auth/refresh-token`
  - Stateless JWT with refresh token rotation and BCrypt hashing.
- **AI Resume Builder & Parsing**:
  - `/api/resume-builder`: Fetch composite candidate profile and saved versions.
  - `/api/resume-builder/upload`: Upload PDF/DOCX resumes for background parsing via Apache Tika + Gemini.
  - `/api/resume-builder/versions`: Tailor and export resumes to ATS Modern, Corporate, Minimal, and other templates in Month-Year format.
  - `/api/resume-builder/versions/{id}/download`: Export resume in PDF, DOCX, or JSON.
- **Semantic & Hybrid Search**:
  - Vector similarity search (`pgvector`) combined with full-text fuzzy matching via OpenSearch.
- **Candidate Recommendations**:
  - `/api/recommendations/candidates/me/jobs`: Smart matching based on vector embeddings and skill intersections.
- **Real-Time Chat**:
  - WebSocket endpoint `/ws` with STOMP protocol for candidate-employer communications.

## Troubleshooting Common Issues

1. **Redis Connection Refused**:
   - If Redis is running on another machine or container, ensure `bind 0.0.0.0` or `protected-mode no` is set in `redis.conf`.
   - The application is equipped with a fail-open `CacheErrorHandler` and rate-limit filter, so standard DB queries will still work if Redis is temporarily unreachable.
2. **OpenSearch Certificate Errors**:
   - The local `OpenSearchConfig` includes an `X509ExtendedTrustManager` that automatically disables SSL verification for local development certificates.
3. **Java Version Incompatibility**:
   - UniHire targets Java 27 toolchain. Ensure your `JAVA_HOME` or `gradle.properties` (`org.gradle.java.home`) points to a JDK 27 installation.
